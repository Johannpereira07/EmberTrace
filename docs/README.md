## Precedence

1. **PRD (01)** is the source of truth for *what* we build: requirements, priorities, behavior.
2. **Data profile (07)** is the source of truth for *facts about the data* (dates, codes, columns). If it contradicts any doc, the data wins and the doc gets corrected.
3. **Implementation Plan (03)** settles what the PRD leaves open (its Appendix A decisions) and owns schedule, ownership and tasks. It must not contradict the PRD.
4. **API Spec (04)** is the contract between backend and frontend, inside the PRD's requirements.
5. **Architecture (02)** covers science and methodology only where nothing above overrides it.

If two docs disagree in a way these rules don't settle, stop and ask the team (see `CLAUDE.md`).
